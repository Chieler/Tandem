# Code Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan phase-by-phase. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let agents run short JavaScript scripts inside an embedded QuickJS engine via a shared per-user `cntctr` daemon that supervises downstream stdio MCP tool servers, enforces per-project grants and schemas, and stores capped/expandable run outputs.

**Architecture:** Four new tables in `kb.db` (`kb.c` — `code_servers`, `code_catalogs`, `code_grants`, `code_runs`) store server registrations, per-instance tool catalogs/generations, per-project grants (keyed by canonical project root and server registration id), and 24 h run outputs outside `entries`/`recall`. A dedicated per-user daemon (`cntctr _code-daemon`, bound to `code.sock` next to `kb.db`) supervises downstream stdio MCP servers (`code_mcp.c`) and executes each script on a dedicated sized run thread with a fresh QuickJS runtime (`code_js.c`) and tri-state C JSON Schema validator (`code_schema.c`). `cntctr.c` forwards `code_*` MCP tools and `cntctr code` CLI commands and serves allowlisted `tools.cntctr.*` reverse-RPC callbacks back through `dispatch_as`.

**Tech Stack:** C11, json-c, SQLite (WAL), pthreads, POSIX Unix sockets + `flock`, vendored `quickjs-ng` (MIT), bash + jq + python3 (fixture & PTY test helper only) for `test.sh`.

**Spec:** `docs/superpowers/specs/2026-11-20-code-mode-design.md`. Read it before each phase; this plan names sections and exact interfaces instead of repeating prose.

## Architecture decisions

### Deliberate spec tightening (SPEC CHANGE)

- **Default-deny for `read` tools:** Spec line 80 says a `read` tool is callable *"once the project has the server"*, while Spec lines 107, 111, and 135 state that user-registered servers are shared and *"another project starts with none."* To eliminate cross-project default exposure on user-shared servers, this plan adopts **default-deny when no access rule matches**: a project "has" a server only once it holds at least one non-`deny` access rule (e.g. `grant <server>.* read`). Every read-class denial explicitly suggests `cd <quoted_root> && cntctr code grant <server>.* read`, and `GUIDE` + `skills/code-mode/SKILL.md` document this rule.
- **v1 positive `allow` exact-tool only:** Positive `allow` grants require an exact tool name (no `*`/`?` globs) so `class_at_grant` binds unambiguously to one tool's effective class; globs remain supported for `read` ceilings, `deny`, and `class:*` overrides.
- **`--trust none` preserves `destructiveHint`:** Spec line 97 says `--trust none` *"treats all its tools as `write`"*. To prevent distrusted annotations from downgrading a self-reported `destructive` tool to `write` and bypassing destructive escalation, this plan ignores `readOnlyHint` only under `--trust none` (`destructiveHint: true` stays `destructive`, all other tools become `write`).

### Challenging the suggested phase order

The suggested 1→8 order (`(1) QuickJS+fixture → (2) kb tables → (3) daemon+status → (4) MCP stdio client → (5) QuickJS run+bridge → (6) agent tools → (7) admin tools+CLI → (8) watch/README/skill`) has three sequencing hazards:

1. **QuickJS async/limits risk is deferred until Phase 5.** The single riskiest new piece (embedding QuickJS cleanly under ASan, sizing pthread stacks above QuickJS's stack cap, measuring active thread CPU via `CLOCK_THREAD_CPUTIME_ID`, and refcounted completion teardown) would wait behind ~1,500 lines of daemon/socket/MCP stdio code. Moving the standalone QuickJS engine + tri-state C schema validator + bridge core up to **Phase 3** (tested on a real sized pthread against an in-process barrier mock) retires the highest technical risk before building IPC.
2. **Admin registration/CLI is deferred until Phase 7, after Phases 4–6 need them.** Moving basic guarded `cntctr code server add|list|remove` (with `cli_admin_guard`, no daemon autostart) and a test-only grant seed hook into **Phase 2**, adding `_test-code-rpc` in **Phase 4**, and placing full admin tools/CLI/guardrails in **Phase 6** ahead of agent tools (**Phase 7**) keeps every phase independently buildable and testable without raw SQL.
3. **Fake MCP fixture belongs with the MCP client that consumes it.** Keeping Phase 1 focused on QuickJS vendoring + Makefile + ASan smoke test and creating `fixtures/fake-mcp.py` in **Phase 5** (alongside `code_mcp.c`) avoids dead scaffolding in Phases 1–4.

**Adopted order:** (1) Vendor QuickJS + Makefile + ASan smoke → (2) `kb.c` tables, grant resolver, `cli_admin_guard` & `cntctr code server add|list|remove` → (3) QuickJS runner, tri-state C schema validator & refcounted bridge core (mock-tested) → (4) Daemon skeleton, socket, lockfile, semver drain, `_test-code-rpc` & `cntctr code status` → (5) Fake MCP fixture + downstream MCP stdio client (init/pagination/per-instance catalogs/atomic recheck), pool, crash/LRU & daemon wiring → (6) Admin tools (`code_server`/`code_grant`/`code_revoke`), full `cntctr code` CLI & human-rule/orchestrator guardrails → (7) Agent tools (`code_find`/`code_run`/`code_expand`/`code_status`) & threaded `tools.cntctr.*` reverse RPC → (8) `watch.sh`, `README.md`, `GUIDE` & skill note.

### Three riskiest architecture decisions

1. **Daemon process model, lifecycle, and deadlock-free version drain**
   - **Risk:** `cntctr` MCP processes are multithreaded (`call_thread`, `fifo_watch`). Bare `fork()` without `exec()` inherits locked mutexes and corrupts SQLite/ASan state; single `fork()` leaves zombies; inheriting harness env leaks API keys/sandboxes. Holding `code.lock` across a synchronous drain deadlocks with a draining daemon that needs `code.lock` to unlink `code.sock`. Mixed versions (`0.5.x` alongside `0.6.x`) can ping-pong drain loops, and `fchdir` for >104-byte macOS `sun_path` races across threads.
   - **Recommendation:** Launch via `cntctr _code-daemon` (dispatched in `cntctr.c:main` after `signal(SIGPIPE, SIG_IGN)`, mirroring `cntctr _notify` at `cntctr.c:5251`) using a **double-fork** (`cntctr.c:845`) + `setsid()` + `execve()` under `fork_mu`, closing all fds > 2 and passing a **scrubbed `envp` built before `fork()`** (`HOME`, `USER`, `PATH`, `LANG`, `LC_ALL`, `TMPDIR`, `SHELL`, `CNTCTR_DB`, `CNTCTR_CODE_SOCK`, plus daemon-wide `CNTCTR_CODE_MAX_SERVERS`, `CNTCTR_CODE_IDLE_SEC`, `CNTCTR_CODE_DAEMON_IDLE_SEC`, `CNTCTR_CODE_DRAIN_GRACE_SEC`, `CNTCTR_CODE_MAX_RUNS`, `CNTCTR_CODE_DAEMON_QUEUE_BYTES` read once at start; under `#ifdef CNTCTR_TEST_HOOKS`, also pass `CNTCTR_TEST_DAEMON_VERSION`, `ASAN_OPTIONS`, `LSAN_OPTIONS`, `UBSAN_OPTIONS`). Per-run limits travel in each `run` request, clamped by hard ceilings. **Only MCP calls autostart the daemon; the CLI never autostarts it.**
   - Place `code.sock` and sibling `code.lock` in `dirname(kb_path)` next to `kb.db` (overridable by `CNTCTR_CODE_SOCK`); drop `fchdir` — if `strlen(sock_path) >= sizeof(sa.sun_path)`, fail immediately naming `CNTCTR_CODE_SOCK`.
   - `hello` carries `{proto: 1, version: CNTCTR_VERSION, db: <canonical_db_path>}` after peer-UID check (`getpeereid`/`SO_PEERCRED`). Reject `db_mismatch` loudly naming both paths and `CNTCTR_CODE_SOCK`. Drain **only when client is newer**; older clients get `version_mismatch: daemon (<d>) is newer than client (<c>); restart your harness`.
   - **Deadlock-free drain protocol:** Client acquires `code.lock` → re-probes `code.sock` → if an older or already-draining daemon answers, sends `drain` (receiving an immediate ack `{"ok":true,"draining":true}` on that connection, which the daemon keeps open until exit), **releases `code.lock`**, waits for EOF on the drain connection (or bounded backoff up to `grace + 5 s`), then re-acquires `code.lock`, re-probes, and spawns only if still absent. On `drain`, the old daemon atomically sets `draining = 1` (while keeping `code.sock` bound: it still completes `hello`+`drain` for any second concurrent upgrader and `status`, rejecting only work RPCs with retryable `"cntctr is upgrading; retry in a few seconds"`), waits up to `CNTCTR_CODE_DRAIN_GRACE_SEC` (default `30 s`) for active runs before cancelling remaining runs with `"daemon upgrading; rerun"`, stops all child servers, **then acquires `code.lock` only for final unlink + listen-fd close + drain-conn close**, releases lock, and exits. Idle exit likewise atomically closes admission (`draining = 1`), takes `code.lock`, unlinks `code.sock`, closes listen fd, and exits; clients retry once under `code.lock` on `ECONNREFUSED`/`ECONNRESET`/EOF-before-hello. Daemon worker threads open their own `sqlite3 *` handle per request.

2. **Threading with QuickJS (stack sizing, owned async state, `CLOCK_THREAD_CPUTIME_ID`, concurrent reverse RPC)**
   - **Risk:** `JSRuntime`/`JSContext` is single-threaded; macOS secondary pthreads default to a 512 KB stack (< 1 MB JS stack, crashing the shared daemon under recursion/ASan). Early termination races with late reader completions and detached reverse-RPC threads. Blocking cold starts, handshakes, stdio writes, or `send(wait=true)` on the run thread or client reader loop deadlocks `Promise.all` or hangs cancellation.
   - **Recommendation:** Vendor **quickjs-ng** (MIT, C11, exact library source list from upstream `CMakeLists.txt` at pinned tag recorded in `vendor/quickjs/UPSTREAM.md` + `LICENSE`); compile vendored `.o` files without `-Werror` and in `cntctr-test` with `-fsanitize=address` only (no UBSan on vendored code), keeping `-Wall -Wextra -Werror -fsanitize=address,undefined` on all cntctr `.c` files.
   - Spawn every run (including `_test-code-js`) on a dedicated pthread with `pthread_attr_setstacksize(&attr, max_stack_bytes + 8 * 1024 * 1024)`, creating `JSRuntime`/`JSContext` on that thread. Measure active JS CPU with `CLOCK_THREAD_CPUTIME_ID` in `JS_SetInterruptHandler`, and wall deadline with `CLOCK_MONOTONIC` checked both in the interrupt handler and between `JS_ExecutePendingJob` iterations (using relative condvar waits).
   - Keep **all** transport work (cold-start spawn, MCP handshake, catalog refresh, stdio writes, reverse RPCs) **off the run thread**. Transfer owned `json_object *args` refs (`json_object_get`/`put`) and copied/pinned metadata across the async boundary; use refcounted `code_call_handle` tokens (status `OK`/`ERROR`/`DENIED`, payload copied under mutex before reader frees it) detached on run exit with `cancel_call` cancelling queued/unawaited work. During `run`, the daemon's connection thread polls `conn_fd` concurrently with the `code_js_run` thread to receive reverse-RPC replies and trigger `code_run_cancel_signal` on client EOF/cancel; the client polls `cntctr.c:cancelled()` in ≤ 200 ms slices and refcounts its reverse-RPC connection state across bounded worker threads (forcing `wait=false` on `tools.cntctr.send`).

3. **JSON Schema validation choice (tri-state C validator over `json-c` vs JS inside QuickJS)**
   - **Risk:** Validating inside QuickJS wastes memory/CPU per run and exposes validation to prototype pollution; failing open naively inside `oneOf`/`anyOf`/`allOf` misclassifies schemas.
   - **Recommendation:** Implement a focused recursive C validator (`code_schema.c`, ~280 LOC) over `json_object *` outside QuickJS supporting `type` (string/array, `integer` vs `number`), `required`, `properties`, `additionalProperties` (bool/subschema), `items`, `enum`, `const`, numeric/string/array bounds, `anyOf`/`oneOf`/`allOf`, and local `#/$defs/` / `#/definitions/` `$ref` (depth ≤ 16). Propagate a **tri-state result** (`SCHEMA_VALID`, `SCHEMA_INVALID`, `SCHEMA_INDETERMINATE` for unsupported keywords like `format`, external `$ref`, non-POSIX `pattern`, or depth cap) through combinators, failing open **only** when the top-level result is `SCHEMA_INDETERMINATE`. Provide field-path errors and Levenshtein name suggestions (≤ max(2, len/3), top 3).

## Global Constraints

- **Build & sanitizers:** C11; all cntctr `.c` files compile with `-Wall -Wextra -Werror -fsanitize=address,undefined` in `cntctr-test`. Vendored `vendor/quickjs/*.c` (file list from upstream `CMakeLists.txt` at pinned tag) compiles without `-Werror` and with `-fsanitize=address` only in `cntctr-test`. Always stage newly created files explicitly with `git add` in every phase (never rely on `git commit -am` for new files).
- **Codebase style:** Match `fmt()`, `ok()`/`fail()`, `sarg()`/`barg()`, `BEGIN IMMEDIATE` transactions in `kb.c`, `fork_mu` + `FD_CLOEXEC` + close fds > 2 (`fleet.c:450-458`), short comments, no new external libraries beyond vendored `quickjs-ng`.
- **Schema version & rollout:** Adding new tables to `kb.c:SCHEMA` has no `MIGRATIONS` entry: decrement `KB_SCHEMA_VERSION`'s offset in `kb.c:128` (`- 11` → `- 10`, bumping version `8` → `9`, and fix the stale comment at `kb.c:126` that says `12`). Older `0.5.x` processes refuse `user_version > KB_SCHEMA_VERSION` (`kb.c:147`), so operators must restart all sessions when activating this release.
- **Project authority root:** Split `resolve_code_cwd(cwd, canon_root)` and `resolve_code_project(pane, canon_root)` (matching `cntctr.c:414,436`): resolve git common dir via `git -C <cwd> rev-parse --path-format=absolute --git-common-dir` (parent if `/.git`), else `cwd`, and **always run `realpath()`** (macOS `/tmp` vs `/private/tmp`). For all MCP `code_*` tools, set `needs_pane = 1` in `TOOL_FNS` (requiring `from=` for attribution when paneless) **and pass `self_pane` (NEVER `caller_pane` from `from=`) to `resolve_code_project(self_pane, canon_root)`** so authority comes strictly from the process-bound pane or the MCP server's own trusted local `getcwd()`, never from `from=`!
- **Threat model & admin guardrails:** `kb.db` and `code.sock` are owned by the same OS user, so grants and CLI/agent checks are a same-user guardrail against mistaken or prompt-injected agents — not a kernel boundary against a process that writes SQL directly. Authority is per pane: `is_orchestrator` proves the MCP process descends from that pane's root process (the pane id in the environment is only a hint), so any process running inside an orchestrator's own pane — including a nested MCP process — shares its authority; that is the documented threat model, not a bug.
  - `is_orchestrator` requires a live process-bound `self_pane` (never `from=`), `pane_alive(self_pane)`, `TMUX(...) == 0` reading `@cntctr_parent` with empty result (fail closed on tmux error), and `!is_reviewer(self_pane)`.
  - `cli_admin_guard(destructive_prompt, summary)` refuses (naming which check fired) whenever: (a) `CNTCTR_ROOT` is set; (b) `$CNTCTR_PANE`/`$TMUX_PANE` is set and tmux fails OR `@cntctr_parent` is non-empty (plain non-tmux terminals skip the tmux check; stale `@cntctr_name`/`@cntctr_harness` tags are not refused after a harness exits); (c) any ancestor process in `ps -A -o pid=,ppid=,comm=` (reusing `find_self`'s walk) has basename `claude`, `codex`, or `agy` — under `#ifdef CNTCTR_TEST_HOOKS` only, stop the walk at `CNTCTR_TEST_ANCESTOR_STOP_PID` (set to `$$` in `test.sh`/`test-cli.sh`) so running tests under a real harness does not break positive CLI tests while fake `claude`/`codex` child wrappers are still caught. When `destructive_prompt != 0`, it additionally requires `isatty(0) && isatty(1)` and interactive `y/N`. Run `cli_admin_guard` **before** any subprocess probe!
  - **Human rule protection:** CLI grants record `granted_by = "human"`. MCP `code_grant` and `code_revoke` refuse to overwrite or delete any row with `granted_by == "human"`. CLI replacing/revoking a human `deny`/`class:*` rule, or CLI replacing/removing a server whose old `reg_id` has any `granted_by == "human"` row, requires `destructive_prompt = 1` (TTY `y/N`).
  - **Server admin scope:** All MCP `code_server` actions (`add`, `list`, `remove`, `discover`, `restart`) require `is_orchestrator`. MCP `add` refuses any name that already names a user-scoped server (shadowing is CLI-only) and may only create a brand-new server name or update a row with `scope_project == caller_canon_root`; MCP `remove`/`restart` may only touch rows with `scope_project == caller_canon_root`. Inside the same `BEGIN IMMEDIATE` transaction (`from_mcp = 1`), `kb_code_server_put`/`del` refuse MCP replace or remove whenever ANY `granted_by == "human"` row exists for the old `reg_id` (`"a human set rules on this server; ask the user"`). Modifying/removing/restarting user-scoped registrations is CLI-only (printing `"dropped N grants in M projects"` when grants are cleared).
- **Server naming, virtual `cntctr`, & CLI hygiene:** Server names match `^[a-zA-Z0-9_-]{1,63}$` and cannot be `"cntctr"`. Reject whitespace in `--cmd` (use repeated `--arg`). List and status outputs may show env keys, never env values. Virtual server `"cntctr"` resolves to `reg_id = "cntctr"`, `owner_project = ""`, and the static allowlist class table across grant/revoke/list/find/check. Shell-quote both `<canon_root>` and `<server>.<tool>` (POSIX `'...'` with `'\''` escaping) in all printed CLI commands.
- **Privilege classes & grants:** Fail closed: `destructiveHint: true` → `destructive`; else `readOnlyHint: true` → `read`; else → `write`. Under `--trust none` (default for MCP `code_server add`), **ignore `readOnlyHint` only** (`destructiveHint: true` stays `destructive`, all others become `write`). Grants bind to `(project, reg_id)`, split `kind='access'` (`allow`/`read`/`deny`) from `kind='class'` (`class:write`/`class:destructive`), default-deny when no access rule matches (SPEC CHANGE above), and restrict v1 positive `allow` to exact tools present in the discovered catalog.
- **Limits & caps (all env-overridable, clamped by hard ceilings):**
  - JS/run: `CNTCTR_CODE_MAX_MB=64` (ceil 256), JS stack `1 MB` (pthread stack `max_stack + 8 MB`), `CNTCTR_CODE_CPU_SEC=10` (ceil 60, `CLOCK_THREAD_CPUTIME_ID`), `CNTCTR_CODE_WALL_SEC=300` (ceil 1800), `CNTCTR_CODE_CALL_SEC=30` (ceil 300), inline preview caps: `CNTCTR_CODE_RESULT_BYTES=16384` (result & logs), `8192` bytes each (calls & denied).
  - Concurrency, queues & C buffers: `CNTCTR_CODE_MAX_SERVERS=6`, `CNTCTR_CODE_MAX_RUNS=8`, `CNTCTR_CODE_MAX_INFLIGHT=16` (per run), `CNTCTR_CODE_MAX_REV_CALLS=4` (reverse RPC workers per run), `CNTCTR_CODE_MAX_QUEUE_BYTES=8388608` (8 MiB queued per run), `CNTCTR_CODE_DAEMON_QUEUE_BYTES=33554432` (32 MiB daemon-wide in-flight replies), reader line cap = `min(CNTCTR_CODE_MAX_MB / 4, 16 MiB)` (default `16 MiB`), `CNTCTR_CODE_IDLE_SEC=900`, `CNTCTR_CODE_DAEMON_IDLE_SEC=60`, `CNTCTR_CODE_DRAIN_GRACE_SEC=30`, `CNTCTR_CODE_RUN_TTL_SEC=86400`, `CNTCTR_CODE_MAX_LOG_BYTES=1048576` (1 MiB), `calls`/`denied` retained cap = `256 KiB` each, stored `result` cap = `4 MiB`, `code_expand` page max = `64 KiB` (UTF-8 boundary aligned).
- **Script cntctr allowlist:** `code_*` tools are never exposed inside scripts. `tools.cntctr.*` allowlist is checked on the client **before** `dispatch_as` (`cntctr.c:3045` pattern): `list`, `recall`, `read`, `board`, `project` (get-only: reject non-empty `key`) as `read`; `note`, `post`, `send` (reject `wait: true`, force `wait: false`), `reply` as `write`.
- **Tests:** Live in `test.sh` (isolated `$TMPD/code_*` dirs and `ONLY=code-*` exit blocks matching `test.sh:3218-3227`) plus `test-cli.sh`. Use barriers/polling, never fragile fixed sleeps.

## Review Focus

1. **Oversized `sun_path` & deadlock-free upgrade drain:** Paths ≥ `sizeof(sa.sun_path)` fail naming `CNTCTR_CODE_SOCK` (no `fchdir`). Two concurrent newer upgraders hitting a daemon with a live run release `code.lock` during drain wait, finish/cancel within `CNTCTR_CODE_DRAIN_GRACE_SEC`, unlink under lock, and spawn one new daemon; older clients never drain a newer daemon. Test in Phase 4.
2. **Native thread stack, async ownership, queue caps & reverse-RPC cancellation:** Recursion runs on a sized pthread (`max_stack + 8 MB`); owned `args` refs and refcounted `code_call_handle` tokens prevent UAF on wall timeout, disconnect, crash, or unawaited promises; `Promise.all` fan-out enforces `CNTCTR_CODE_MAX_INFLIGHT` & queue byte caps; client `cancelled()` wakes reverse RPCs cleanly under ASan. Test in Phase 3, Phase 5 & Phase 7.
3. **MCP protocol, per-instance catalogs & atomic live recheck:** Fixture enforces `initialize` + `notifications/initialized`, paginates `tools/list`, and mutates both class and same-class schema on restart; `--isolated` projects maintain separate `code_catalogs` rows; `code_pool_dispatch` re-validates both grant and schema atomically with enqueue on `(reg_id, meta_gen)` change or revocation; `--trust none` preserves `destructiveHint: true`. Test in Phase 5.
4. **Authority root, human-rule immutability & agent CLI blocking:** Paneless `from=<victim>` cannot access victim's project grants, `code_expand` victim's `run_id`, or dispatch reverse `board`/`post` into victim's pane/project; orchestrator cannot overwrite/revoke `granted_by="human"` rows (including via `code_server` replace/remove) or shadow/modify user-scoped servers; `cli_admin_guard` blocks `CNTCTR_ROOT`, `@cntctr_parent` panes, and `claude`/`codex`/`agy` ancestor processes (even with a PTY) while allowing humans in plain terminals or panes where a harness exited; worker `code_server(discover)` spawns no process. Test in Phase 2, Phase 6 & Phase 7.
5. **Shell-quoting & apostrophe paths:** Escalation and denial commands properly single-quote paths containing apostrophes (`proj's dir`) and tool names so pasting into a shell executes cleanly. Test in Phase 6 & Phase 7.
